# worklog 仕様

## 目的

Claude と作ってきたものについて **「いつ・なぜそうなったか」を、人間も Claude もタグから引ける状態にしておく**。

- 自動モードで最後まで走らせても、何をしたか・何を人間が確認すべきかが後から分かる
- セッションをまたいでも、Claude がプロジェクトの経緯を把握できる

仕様書を作ることは目的にしない。記録は投稿の積み重ねで、タグから逆引きできればよい。

## 画面づくりの原則

**フィルタ機能は搭載しない。見やすさは画面の作り（何を目立たせ、何を畳むか）で解決する。** これを最も重要な方針とする。

- 絞り込み・検索欄・表示切り替えのような操作を増やすと、画面の情報量が増え、使う人に判断を委ねることになる
- 代わりに、情報の重みを最初から画面で表現する。決定と要確認は目立たせ、試行錯誤は1行に畳み、自動記録は薄い1行にする
- 話題から探したいときは、タグによる逆引き（ナビゲーション）で辿る

## 利用前提

| 項目 | 前提 |
|---|---|
| 利用環境 | クラウド（claude.ai/code）と手元の PC の両方。クラウド優先 |
| 見る人 | 自分と Claude だけ |
| 配布 | Claude Code プラグイン（MCP サーバー・スキル・hook を一括で入れる）。npm は使わない |
| プロジェクトの単位 | 1リポジトリ＝1プロジェクト。記録はそのリポジトリの `.worklog/` に入るので、所属は作業したリポジトリで自動的に決まる |

## データ

### 保存場所と運用

- プロジェクトの `.worklog/` に置き、**git にコミットする**（クラウドのセッションはコンテナごと消えるため）
- 投稿は **セッションごとに別ファイル**（`.worklog/sessions/<日時>_<セッションID先頭8桁>.jsonl`）。ブランチをまたいでもマージで衝突しない
- 投稿から作り直せるもの（HTML ビューア、hook の一時状態）はコミットしない（`.worklog/.gitignore`）
- 投稿ファイルは GitHub の差分表示で折りたたまれるよう自動生成扱いにする（`.worklog/.gitattributes`）
- 手元だけで使うプロジェクト向けに、`WORKLOG_COMMIT=false` で `.worklog/` 全体をコミット対象外にできる

### 投稿

1行1投稿の JSON（JSONL）。追記のみで、書き換えない。要約など後から付け足す情報は、`{"patch": "<投稿ID>", ...}` の行を追記して読み込み時に合成する。

| 項目 | 内容 |
|---|---|
| `id` | 短い ID（例 `0926-1332-k3f`）。返信や参照に使う |
| `ts` | 日時（ISO 8601, UTC）。表示は見る側のタイムゾーン |
| `author` | `human`（あなた）/ `claude` / `auto`（自動記録） |
| `kind` | 下表 |
| `text` | 本文 |
| `summary` | 長い指示・返答の要約（後から追記する） |
| `tags` | タグ（`#` なし） |
| `re` | 返信先の投稿 ID |
| `reason` | 理由（主に決定） |
| `files` | 関係ファイル / 変更ファイル |
| `next` | 次にやること（まとめ） |
| `commands` / `tests` | 自動記録の実行コマンド・テスト結果 |

| kind | 書く人 | 意味 |
|---|---|---|
| `prompt` | 自動（人間の指示） | 指示文（1000字まで。改行は保持） |
| `reply` | 自動（Claude の返答） | そのターンの Claude の最後の返答（4000字まで） |
| `idea` | Claude | 思いつき・要望の記録 |
| `decision` | Claude | 決定と理由 |
| `question` | Claude | 人間に確認・判断してほしいこと。`answer` の返信が付くまで「未解決」 |
| `answer` | Claude | 質問への回答（人間の返事を Claude が記録） |
| `issue` | Claude | 問題・失敗 |
| `result` | Claude | 成果・検証結果 |
| `note` | Claude | メモ |
| `summary` | Claude | 区切りのまとめと次にやること。次のセッションへの引き継ぎに使う |
| `activity` | 自動 | そのターンの変更ファイル・主なコマンド・テスト結果 |

### タグ

- カテゴリはタグだけで表す。最初に決めず、使いながら増やす
- 投稿時に、既存タグと大文字小文字・全角半角だけが違うものは既存の表記にそろえる
- 意味が同じ別表記（`#login` と `#ログイン` など）は統合せず、Claude が `question` で提案する

## 機能

### MCP ツール

| ツール | 内容 |
|---|---|
| `worklog_context` | 引き継ぎ情報：未解決の質問、前回のまとめと次にやること、タグ一覧、最近の投稿 |
| `worklog_post` | 投稿する（Claude が書く kind） |
| `worklog_answer` | 質問に回答を付けて解決にする |
| `worklog_tag` | タグの逆引き：そのタグの投稿を時系列で、関連タグつきで返す |
| `worklog_search` | 全文検索 |
| `worklog_view` | HTML ビューアを生成してパスを返す |

### 自動記録（hook）

| hook | 動作 |
|---|---|
| `SessionStart` | 引き継ぎ情報を Claude に渡す |
| `UserPromptSubmit` | 指示文を `prompt` として投稿 |
| `PostToolUse` / `PostToolUseFailure` | 変更ファイル・コマンド・テストの成否を一時的に貯める |
| `Stop` | 貯めた内容を `activity` 1件にまとめて投稿し、Claude の返答を `reply` として記録し、ビューアを更新する。自動モードの終了チェックもここで行う |

貯めた変更は、Claude が `worklog_post` するたびにも先に書き出す。作業の記録が起きた順に並ぶようにするため。

読み取りだけのコマンド（`ls`, `cat`, `grep`, `git status` など）はコマンド一覧に載せない。

### 要約

長い指示（80字超）と返答（140字超）は、Claude が返答を終えたあとに裏で軽量モデル（既定は Haiku）が1文に要約し、`patch` 行として追記する。

- Stop hook は要約を待たずにすぐ返る（別プロセスで実行）
- ユーザー自身の Claude Code のログインで `claude -p` を呼ぶ。ツール・MCP・プロジェクト設定は読み込まない
- 要約用の実行が自分自身をログに記録しないよう、`WORKLOG_DISABLED=1` を付けて呼ぶ
- 失敗したときは要約なしのまま（画面は原文を折りたたんで表示）。次のターンで未要約のものを再度まとめて要約する
- `WORKLOG_SUMMARIZE=false` で無効、`WORKLOG_SUMMARY_MODEL` でモデルを変更できる

### 自動モードの終了チェック

権限モードが `auto` / `bypassPermissions` / `dontAsk` のとき、そのターンにファイル変更などの作業があったのに Claude の投稿がひとつもなければ、終了を1回止めて投稿を促す。対話中のモードでは止めない。

### HTML ビューア

`.worklog/view/index.html`。ブラウザで開くだけで見られる（サーバー不要）。クラウドでは Claude が Artifact として公開し、スマホからも見られるようにする。

| 画面 | 内容 |
|---|---|
| タグ | **タグの関係図**（丸＝タグ、大きさ＝記録の数、線＝同じ記録に一緒に付いたタグ、太さ＝その回数、黄色＝未回答の確認がある話題）と、その下にタグ一覧（件数・最終更新）。丸か行を押すとタグごとの逆引きページ（投稿の時系列と関連タグ）へ。マウスを重ねると、そのタグとつながるタグが強調される |
| 要対応 | 未解決の質問 |
| セッション（最初の画面） | セッション一覧（最初の指示・件数・まとめ）→ セッションごとの**チャット表示**（下記） |
| スレッド | 投稿をクリックすると返信のつながりを表示 |

### セッションのチャット表示

- 指示は右の吹き出し、Claude の返答は左の吹き出し。要約があれば要約を出し、原文は開いて読む
- **決定（`decision`）と要確認（`question`）は Claude の小さな吹き出しとして流す**。やり取りの中で何が決まったかが一目で追えるようにするため
- 種類は文字のラベルで示さず、吹き出しの見た目で表す（ラベルの行は情報量を増やすだけなので置かない）。決定は緑の枠と行頭の◆、要確認は黄色の枠と行頭の「?」。未回答の要確認は黄色く塗り、右上に点を付ける
- それ以外（問題・成果・メモ・変更など）は、吹き出しの間に「問題3件（解決済み）・成果1件・変更4件 ✗✗✓」のような1行に畳む。開くと時刻つきで1件ずつ見える
- 問題の「解決済み」は、Claude がその問題に返信した場合、または同じセッションで後からテストがすべて通った場合に付く
- ターンの所要時間（5分以上のとき）を表示する。作業の記録が多い長いターンでは、返答を折りたたまずに表示する

## やらないこと

- 仕様書の自動生成・書き換え、矛盾の自動検出
- ビューアからの書き込み（返信は Claude との会話で行う）
- フィード（全記録を時系列に並べる画面）。セッションのチャット表示と内容が重なるため外した。必要になったら追加する
- 複数のリポジトリにまたがるプロジェクトの扱い（リポジトリ間での記録の合流や、記録専用リポジトリへの集約）。複雑になるため対象外
