# worklog

Claude Code に入れておくと、**Claude が「何を・なぜ」したかを自動で記録し、あとからチャットのように読み返せる** プラグインです。

- 自動モードで最後まで任せても、途中で何が決まり、何につまずき、何を確認してほしいのかが後から分かります
- 次のセッションの Claude が、前回までの経緯（まとめ・次にやること・未回答の確認）を引き継いで作業を始めます
- 話題ごとにタグが付くので、「この機能、なんでこうなったんだっけ？」をタグから辿れます

## はじめる

Node.js 20 以上が必要です。

### 手元の PC で使う

Claude Code で次の2行を実行します。

```
/plugin marketplace add GASHIRA-E/claude-section-mcp
/plugin install worklog@gashira-e
```

### クラウド（claude.ai/code）でも使う

クラウドのセッションには、手元でインストールしたプラグインは入りません。使いたいリポジトリの `.claude/settings.json` に次を書いてコミットしてください。手元の Claude Code でも、そのリポジトリを開けば同じ設定で有効になります。

```json
{
  "extraKnownMarketplaces": {
    "gashira-e": { "source": { "source": "github", "repo": "GASHIRA-E/claude-section-mcp" } }
  },
  "enabledPlugins": { "worklog@gashira-e": true },
  "env": { "WORKLOG_TZ": "Asia/Tokyo" }
}
```

`WORKLOG_TZ` は記録の時刻に使うタイムゾーンです。クラウドは UTC で動いているので、日本時間で残したい場合は入れておいてください。

### 入ったかどうかの確認

Claude に何か作業を頼んだあと、リポジトリに `.worklog/` フォルダができていれば動いています。

## 使い方

**特別な操作はいりません。** いつも通り Claude に作業を頼むだけで記録されます。

| 誰が | 何を記録するか |
|---|---|
| 自動 | あなたの指示、Claude の返答、変更したファイル、テストの成否 |
| Claude | 決めたこととその理由、つまずいた問題、できたこと、あなたに確認してほしいこと、区切りのまとめ |

長い指示や返答は、裏で短い1文に要約されます（作業は待たされません）。

### Claude に頼めること

- **確認事項に答える**：Claude からの確認に会話で答えると、回答として記録され、未回答の一覧から消えます
- **「〇〇の経緯を教えて」**：Claude がタグから過去の記録を調べて答えます

### ログを見る

- **手元の PC**：`.worklog/view/index.html` をブラウザで開いておくだけです。画面は Claude が返答するたびに自動で作り直されるので、再読み込みすれば最新になります。Claude に頼む必要はありません
- **クラウド**：`/worklog:view` と打つと、Claude が画面を公開してリンクを渡します。2回目からは同じリンクの中身が新しくなります

`/worklog:view` のやり取り自体はログに残りません。「作業ログを見せて」と頼んでも同じように画面は出ますが、その指示と返答はログに残ります。

### 自動モードで使うとき

作業したのに何も記録しないまま終わろうとすると、Claude は1回だけ止められて記録を促されます。人が見ていない間の判断が、必ずログに残るようにするためです。対話しながら使っているときは止められません。

## 画面の見方

画面は3つです。操作で絞り込む機能はなく、大事なものが目立つように並べています。

### セッション（最初の画面）

Claude とのやり取りを、チャットのように表示します。

| 見た目 | 意味 |
|---|---|
| 右の吹き出し | あなたの指示 |
| 緑の枠・行頭に ◆ | Claude が決めたこと（下に理由） |
| 黄色の吹き出し・行頭に「?」・右上に点 | あなたへの確認で、まだ答えていないもの |
| 点線の枠の1行 | 間の試行錯誤。「問題3件（解決済み）・変更4件 ✗✗✓」のように畳まれていて、押すと中身が開く |
| 左の吹き出し | Claude の返答 |

### タグ

タグのつながりを図で表示します。丸が大きいほど記録が多く、線は同じ記録に一緒に付いたタグ、黄色は未回答の確認がある話題です。丸を押すと、その話題の記録を古い順に読めます。

### 要対応

あなたがまだ答えていない、Claude からの確認事項だけが並びます。

## 大事な注意

> **記録はリポジトリにコミットされます。** 既定では `.worklog/sessions/` をコードと一緒にコミットします。クラウドのセッションは終了するとコンテナごと消えるので、コミットしないと記録が残らないためです。

そのため、次の点に気をつけてください。

- **チームのリポジトリで使う場合**：あなたの指示文（最大1000字）や Claude の返答が、そのリポジトリを見られる全員に見えます。使う前にチームと合意するか、`WORKLOG_COMMIT=false` で記録をコミットしないようにしてください（その場合、クラウドのセッションでは終了時に記録が消えます）
- **指示に秘密情報を書かない**：パスワード、API キー、個人情報などを指示に書くと、そのまま記録されます
- **要約に少しトークンを使う**：長い指示・返答の要約に、軽量モデル（Haiku）を1ターンあたり数百トークン程度使います。不要なら `WORKLOG_SUMMARIZE=false`

## 設定

`.claude/settings.json`（またはユーザー設定）の `env` に書きます。

| 変数 | 既定値 | 内容 |
|---|---|---|
| `WORKLOG_TZ` | 動いている環境の設定 | 記録の時刻に使うタイムゾーン（例：`Asia/Tokyo`）。画面の表示は、見る人の端末のタイムゾーンになります |
| `WORKLOG_COMMIT` | `true` | `false` にすると `.worklog/` をまるごとコミットしない |
| `WORKLOG_SUMMARIZE` | `true` | `false` にすると、長い指示・返答を要約しない |
| `WORKLOG_SUMMARY_MODEL` | `haiku` | 要約に使うモデル |
| `WORKLOG_ROOT` | リポジトリのルート | `.worklog/` を置く場所 |

## 困ったとき

| 症状 | 対処 |
|---|---|
| `.worklog/` ができない | `/plugin` で worklog が有効になっているか、Node.js 20 以上が入っているかを確認してください |
| 時刻が9時間ずれている | `WORKLOG_TZ` を `Asia/Tokyo` にしてください |
| クラウドで記録が消えた | `.worklog/sessions/` がコミット・push されているか確認してください |
| 記録を消したい | `.worklog/sessions/` の中のファイルを消してください。セッションごとに1ファイルです |

## 記録の中身（参考）

```
.worklog/
├── sessions/        # 記録。Claude のセッションごとに1ファイル（コミットする）
├── view/            # ログを見る画面（自動で作り直すので、コミットしない）
├── .state/          # 一時ファイル（コミットしない）
├── .gitignore
└── .gitattributes   # GitHub の差分表示で記録ファイルを折りたたむ
```

セッションごとに別ファイルなので、複数のブランチで作業してもマージで衝突しません。

## 開発する人向け

仕様と決めたことの経緯は [docs/SPEC.md](docs/SPEC.md) にあります。

```bash
npm install
npm run check   # 型チェック + テスト + ビルド
```

- ソースは `src/`、テストは `test/`（Node 22.18 以上の組み込み TypeScript 実行を使用）
- `dist/` はプラグインが `npm install` なしで動くよう、依存込みでバンドルしてコミットしています。`src/` を変更したら `npm run build` して `dist/` もコミットしてください
